# PPT制作素材包

用于模块一汇报制作。所有内容仅落盘，本文件夹不纳入本轮Git提交。

先看 `01_内容与数据/逐页讲稿.md` 和 `01_内容与数据/模板核对.md`，再使用数据表、运行截图与源码。

| 目录 | 内容与用途 |
| --- | --- |
| 01_内容与数据 | 逐页讲稿、模板核对、方法/用例/覆盖率数据、硬件信息、提交后Git统计 |
| 02_运行证据 | 原始日志、JUnit、HTML报告、覆盖率JSON、修复前证据、源码指纹及提交后复验 |
| 03_截图 | 原始报告及真实日志展示页的浏览器截图；截图说明见讲稿 |
| 04_参考稿 | 旧版PPT与逐页PNG、Word与Excel参考件；不是已验收终稿 |
| 05_源码与配置 | 本次测试代码、共享fixture、配置及三个被测源码文件 |
| 06_课程要求与模板 | 原始课程PDF和教师模板 |

## 使用时必须统一的口径

- 模块一独立基线：199项收集、188通过、0失败、11项CUDA跳过；15.55秒；三个指定模块语句/分支综合覆盖79.43%。
- 提交后复验同时运行模块一和模块二：结果以新增的提交后复验日志为准，不能把两模块总数写成模块一数量。
- 原始HTML插件Summary显示188 tests，这里是未跳过的执行数；收集总数应查JUnit和日志，为199。
- 截图来自真实历史报告或原始日志展示页面，不是新构造的终端运行界面；页面注明来源。新复验另存，未覆盖历史证据。
- 04_参考稿中的成员比例对应提交前的2e40c0c快照，且有未提交措辞。制作最终PPT时使用01中的提交后统计，保留AI辅助说明；代码归属不等于课程总工作量。
- 原PPT第4页“根目录pytest入口限定模块一收集范围”不准确：根配置同时收集module1和module2，只有显式指定tests/module1/才单独执行模块一。以本包逐页讲稿为准。
- 不把CUDA跳过写成通过，不把最小Conv2d集成测试描述为完整TRD训练，不把模块二归一化缺陷重复计入模块一3项缺陷。
- 视频及现场演练的形式、三人讲解分工和实际工作量占比尚待讨论。

## 复现命令

在完整仓库根目录运行（05为源码参考副本，不是独立可安装项目）：

```powershell
& 'D:\Anaconda\envs\AI_common\python.exe' -m pytest tests/module1/ --cov --cov-config=.coveragerc --cov-report=term-missing
```

无需服务器即可双击打开02中的HTML报告。制作过程中使用的本地预览服务器只用于保存截图。
